# 🌊 Процесс 1 — образовательный игровой бот для мессенджера MAX

**Процесс 1** — интерактивная образовательная игровая система в формате визуальной новеллы с элементами производственного симулятора, разработанная на Python с использованием MAX API.

Пользователь выступает в роли оператора экстренной линии связи корпорации, управляющей сетью глубоководных исследовательских станций. Его задача — обрабатывать входящие обращения со станций, анализировать возникающие проблемы и принимать управленческие решения в условиях ограниченных ресурсов.

Проект объединяет игровой формат и обучение: пользователь проходит сюжетные главы, изучает учебные материалы, анализирует бизнес-ситуации и применяет инструменты управления процессами, такие как распределение ресурсов, анализ рисков и принятие решений на основе доступных данных.

Каждое действие пользователя влияет на состояние станции, отношения с фракциями и итоговый результат прохождения, позволяя моделировать реальные задачи бизнес-аналитики и менеджмента.

## 🎯 Цель проекта

Цель проекта — повысить эффективность изучения бизнес-процессов и управленческих дисциплин студентами за счёт применения интерактивных игровых методик, а также предоставить преподавателям дополнительный инструмент для проведения промежуточной аттестации и оценки знаний.

Проект направлен на:

- повышение вовлечённости студентов в учебный процесс;
- применение игровых подходов к обучению и контролю знаний;
- поддержку мотивации студентов на протяжении всего курса обучения;
- использование вариативных заданий и различных форм представления материала;
- упрощение изучения сложных дисциплин через практическое взаимодействие;
- создание нестандартного формата подачи учебного материала, способного удерживать внимание обучающихся.

<summary><h1>👤 Основной пользовательский сценарий</h1></summary>

<br>
Пользователь взаимодействует с ботом через MAX Messenger.

Основной сценарий работы:

1. Пользователь запускает бота командой `/start`.
2. При первом входе проходит вступление и регистрацию.
3. После регистрации создаётся профиль пользователя, а состояние игры сохраняется в Redis.
4. После успешной регистрации пользователь получает доступ к главному меню.

Основные возможности меню:

- 🎮 Прохождение игровых глав;
- 📚 Изучение учебных материалов;
- 🌐 Просмотр информации о проекте через WebApp;
- 🤝 Просмотр репутации с игровыми фракциями;
- 🎁 Получение стикерпака и дополнительных материалов.

Во время прохождения игры пользователь:

- принимает управленческие решения;
- изменяет игровые ресурсы;
- влияет на отношения с фракциями;
- получает индивидуальный результат прохождения.

После завершения сюжетной линии формируется итоговая концовка на основе принятых решений и состояния игровых параметров.

## Пошаговый сценарий проверки

1. Открыть бота в MAX Messenger.

2. Пройти процесс регистрации пользователя:
   - ввести имя пользователя;
   - проверить корректность валидации имени;
   - убедиться в создании профиля пользователя.

3. Открыть главное меню бота и проверить доступность основных разделов:
   - игровой сценарий;
   - учебные материалы;
   - информация о проекте;
   - система репутации;
   - дополнительные возможности.

4. Запустить игровую главу и пройти несколько этапов сценария.

5. Выполнить различные сюжетные действия:
   - сделать выбор в игровых событиях;
   - проверить изменение ресурсов;
   - проверить изменение репутации фракций;
   - проверить сохранение выбранных решений.

6. Проверить восстановление состояния пользователя:
   - продолжить взаимодействие после повторного входа;
   - убедиться, что прогресс и данные пользователя сохранены.

7. Проверить обработку некорректных действий:
   - отправить сообщение вне текущего сценария;
   - убедиться, что обработчик `Last Stand` корректно обрабатывает неизвестные сообщения.

## 🧩 Общая архитектура

Проект построен по модульной архитектуре:

- **MAX Messenger** — пользовательский интерфейс взаимодействия;
- **MAX API** — слой связи между ботом и мессенджером;
- **Python Backend** — обработка сообщений, игровая логика и управление состоянием;
- **Redis** — хранение данных пользователей и игрового прогресса;
- **WebApp Bitrix24** — веб-интерфейс и форма обратной связи.
- **Docker Compose** — управление контейнерами и запуском сервисов.

## 🛠 Используемые технологии

- Redis

<summary><h1>🗄 Структура хранения данных Redis</h1></summary>

<br>

Для хранения состояния пользователя и игрового прогресса используется Redis.

Redis содержит данные о профиле игрока, ресурсах станции, прохождении сюжетных линий и репутации среди игровых фракций.


| Ключ Redis | Тип | Пример значения | Назначение |
| :---: | :---: | :---: | :--- |
| `last_message` | Object | `SendedMessage(...)` | Последнее отправленное сообщение игроку |
| `last_media` | Object | `InputMedia(...)` | Последнее отправленное медиа |
| `name` | String | `Данил` | Имя игрока |
| `briefing` | Integer | `0-1` | Прохождение вступительного брифинга |
| `finance` | Integer | `0-20` | Текущий бюджет игрока |
| `energy` | Integer | `0-10` | Текущий уровень энергии станции |
| `food` | Integer | `0-10` | Количество запасов еды |
| `odyssey` | Integer | `0-1` | Прогресс сюжетной линии «Одиссея» |
| `trees` | Integer | `0-1` | Состояние сюжетного выбора |
| `radar` | Integer | `1-3` | Состояние радара |
| `food_update` | Integer | `0-1` | События обновления запасов |
| `ch1_scientist` | Integer | `-1...1` | Репутация с учёными |
| `ch1_security` | Integer | `-1...1` | Репутация с охраной |
| `ch1_worker` | Integer | `-1...1` | Репутация с рабочими |

DEBUG=False

| MAX API | HTTPS (443) | Взаимодействие бота с внешним API мессенджера MAX |
| Bitrix24 WebApp | HTTPS (443) | Работа веб-интерфейса проекта |

### Docker-сеть

Redis не открывается наружу сервера и используется только внутри Docker Compose.

Подключение приложения к Redis выполняется через имя сервиса:

```env
REDIS_HOST=redis
REDIS_PORT=6379
```

<summary><h1>⚠️ Работа с тестовыми данными и ограничения</h1></summary>

<br>

На текущей версии проекта существуют следующие ограничения:

- Имя пользователя при регистрации:
  - поддерживается только кириллица;
  - максимальная длина имени — 20 символов.

- Для работы бота требуется доступ к MAX API.

- Данные пользователей сохраняются в Redis, поэтому при удалении Docker Volume прогресс пользователей будет потерян.

- Текущая версия содержит ограниченное количество игровых глав.

- Динамическая генерация сюжетных веток не реализована и запланирована в следующих версиях.

- WebApp Bitrix24 является облачным сервисом и требует отдельной настройки интеграции. Работа компонента зависит от корректной конфигурации приложения в Bitrix24. Веб-интерфейс доступен через отдельное приложение Bitrix24.

- Прохождение игры рассчитано на одного пользователя в отдельном диалоге MAX.

- Из-за высокой скорости отправки и обработки сообщений в MAX API возможна отправка пользователем нескольких сообщений подряд. Для обработки таких ситуаций реализован обработчик `Last Stand`, который принимает неизвестные или некорректные действия пользователя и предотвращает нарушение основного сценария работы бота.
